# R2.3 · 寝居日常调度接口与连续排演

2026-10-22，接续用户对 R2.2“我觉得可以，按交接包和流程继续”的认可。基线为 PR #26 的 `856dd101431e3335a3b845cfd588b2fc00f37dc0`，保留本分支寝居结构、材质、灯光和动作流程。不合并 main、不覆盖正式入口。

## 这一批做了什么

- `life-bridge.js` 接收原系统提供的只读快照与显式行动请求，调用既有 `requestActivity`，没有另建健康/作息/药品/主线规则。
- 每个请求带来源、ID、单调序号、发生时间和到期时间；拒绝重复、乱序、过期、未来时间、未知动作。忙碌时仅保留最新一项，避免补演积压任务。
- 手动接管停止自动排程；重新启用后只接受新请求。隐藏/恢复页面清除旧排程；伤病、睡眠、离场、权限撤回、时钟逆跳中止自动动作。坐卧转移仍遵循 R2.2 的安全停稳处理。
- 独立页新增“日常生活排演”：自动完成看书 → 停留 → 取药服药占位演示 → 停留 → 回榻休息，结束后停住。可随时停止；下一次需要主动重新开始。
- 性能记录增加调度状态及请求来源；明确 `implementation: placeholder`、`claimVisibleAction: false`、`businessOutcome: null`，不会把示例动作当成正式用药或游戏事实。

## 原系统的接线契约

```js
const bridge = createLifeSceneBridge(scene);
bridge.setSnapshot({world, state, sisterSleeping, permittedPoses});
bridge.resume(); // 外部调度器选择启用，默认关闭
bridge.submit({
  id: 'source-owned-stable-id',
  sequence: 1, // 同一来源流内递增；新流需新建 bridge
  source: 'autonomy', // 独立样板使用 lab
  activity: 'read', // walk / sit / read / medicine / lie / rest
  requestedAt: authoritativeTimestamp,
  expiresAt: authoritativeTimestamp + 60000
});
bridge.tick({paused});
bridge.setVisible(!hidden);
```

请求有效期上限 5 分钟，在开始执行前校验。调用者提供真实权威时间、来源 ID 和明确姿态许可；不能从标题或 AI 文案推断健康许可。每个实例对应一个来源流，不把其他流的序号混入。取消/手动接管后，已消费 ID 不会重播。已启动的转移不会因排队请求过期而瞬移。

`routine-demo.js` 是明确标注的实验 fixture，仅在独立样板内编排示例请求；它不是生产作息，不写生活台账。原 `world.js`、`bedroom-behavior.js`、`engine.js`、`companion.js`、存档与离线纪事均保持字节不变。正式生产页面尚未调用此接口；当前完成的是接口与隔离接线验证，不能称作正式自主生活已经换成 3D。
