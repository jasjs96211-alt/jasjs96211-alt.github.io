# 寝居 R2.2 · 实体屏风与日常行动衔接

日期：2026-10-22。基于 PR #26 的 `feature/bedroom-scope-r2-20261021`，继续既有寝居；不合并 main，不部署正式站点，不扩其他区域。正式人物由用户制作，已有角色图片、收藏资产和 R1 模型导出不变。

## 本轮修改

- 取消 R2.1 的自动透明处理，屏风、床帘、床柱保持原有不透明度、深度写入和投影。遮挡射线只记录诊断信息，不改材质。
- 三扇屏风移到入口前方 z=-2.1 米，轻微折角、修窄框架，保留入门后的真实遮挡。入场路线从门后绕右侧进入主活动区；书案、床侧和药柜前方留出视线。
- 木材纹理减少规则条纹，加入低反差多尺度变化、独立粗糙度；织物、纸、灰泥采用不同细节尺度。地板色差降低，床头改为嵌板与横枨，桌案增加结构性牙板/枨子，前景桌改为四足，药柜调整柜脚与帽沿。枕褥、被面起伏、帘褶更克制。
- 夜间降低全局补光与月光，纸灯提供距离衰减的局部暖光。床边灯在标准档投射局部阴影；低性能档保留局部照明、关闭点光投影。灯罩不遮挡自己的内部光源。
- 日常行动采用连续流程：起身/移到床沿 → 转向路径 → 避障行走 → 停步 → 面向交互点 → 坐下/伸手取书/取药持碗/服药/卧下/休息。忙碌时禁止叠加请求；新增取消按钮。行走取消在当前位置收住步态，坐卧转移取消先完成当前支撑过渡，之后丢弃剩余步骤。
- 快照权限变化立即终止演出并显示允许的安全姿态；健康恢复不会重启被取消的任务。只改变时辰不会重置当前动作。暂停、隐藏标签页、过大时间间隔不推进动作。
- 路径检查由间隔采样改为线段与膨胀碰撞框的精确相交测试，修复桌角漏检。

## 状态与模型接口

`createActionFlow(driver)` 仅消费只读事实和视觉 dt，输出 activity / phase / busy / cancelling / moving / distance。`requestActivity(id)` 在忙碌或权限不足时返回 false；`cancelActivity()` 不产生业务结算。流程不读取、保存或回写健康、药品、主线、存档、自主生活或离线纪事。

`driver.transitionTo({pose,position,yaw,gesture})` 返回 0～1 的采样函数；`walk(position,yaw,distance)` 仍支持连续位移。现有占位代理通过关节四元数和位置插值衔接，未来 GLB 使用动画混合。GLB 仍要求米制、+Y 向上、+Z 朝前、脚底原点/约 1.7 米站高，专用运行时实例；idle/walk/sit/lie/read/medicine/rest 片段和 grip_left/grip_right/head_anchor 锚点沿用既有契约。位移动画须为 in-place，避免和场景根节点位移重复；sit/lie/medicine 为单次保持末帧，其余循环。尚未用用户正式 GLB 验证，动作长度、接触点和混合需在接入时校准。

## 验证记录

- 27 项相关 Node 测试通过（21 项场景 + 6 项共用人物事实），涵盖连续流程、取消/再行动、睡眠/伤病/缺席/时间争议、权限撤回、不同帧率终点、屏风保持实体、全路线碰撞与资源哈希。
- `npm run build` 通过；独立 HTML 包含当前模块与本地 Three.js，无 CDN 依赖，不导入生产引擎。
- 2026-10-22 真实远程 Chrome 打开 R2.2，页面版本和错误界面可读取。浏览器报 `GL_VENDOR = Disabled, GL_RENDERER = Disabled`、`Error creating WebGL context`。实际三维渲染未启动；FPS、GPU 帧耗时、视觉验收均不可用。没有用静态图片代替场景。
- CPU 场景清单：314 个网格、22,168 个三角形、5 张 128×128 程序纹理（不含占位角色）。这是几何清单，不是实测 draw calls 或 FPS。
- Windows Chrome、手机实机的光照、遮挡和帧率待用户体验；页面“试验条件与性能记录”可导出本机数值。

## 明确限制

此轮是更细致的程序场景和占位流程，不是已经验收的写实成品或正式动画。手部抓握、书碗交接、脚底约束、床面支撑与衣物碰撞还没有 IK/物理求解；坐卧和起身可能仍有滑移感。急性伤病/离场等外部权限变化为保护状态，会立即重置姿态而非继续过渡。阅读/服药道具仍为演示代理，不会扣药或治疗。

现有 GitHub Pages 流程整站发布会覆盖生产，因此本轮不触发。沿用可下载、自包含的 `Wendao-Bedroom-R2.2-PR26.html` 供 Windows Chrome 双击体验；这不是新建预览工程，也不是公网托管链接。等待用户画面反馈后集中修改。
