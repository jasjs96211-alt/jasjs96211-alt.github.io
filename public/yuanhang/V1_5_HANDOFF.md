# 温知遥陪伴修炼与 RPG 状态 v1.5

本轮在主线 `e8147e088d517e4b889acd5e3794cfd76aae994e` 上增量实现，分支 `codex/wendao-v15-companion-vitals`。复用草稿 PR #7 的 `eb16e93aa7078ab08f7ce113ed853a2d0cc4b3b0` 陪伴脚本、样式、活动测试和原计时器桥接，逐项适配最新舞台照护、30分钟监管、作息与自主日程；没有用 PR #7 的旧 app 覆盖当前主线。

## 已完成

- 陪伴入口、25/45/60分钟原专注计时器桥接、暂停/继续、带原确认的重置、进入原专注页。只由原计时器写一次学习记录；关闭或重置不冒充完成，完成提示核对同 ID 的真实 timer 记录。
- 进入陪伴暂停逐字、自动播放与跳过，不标记未读。返回书房后「续读」回到暂停的阅读位置。疗养/商议、自由交谈、状态/用膳可从陪伴层进入既有舞台流程。
- 日常按世界时间六分钟切换书案、药架、竹窗或休息；病中/受伤始终在榻边低活动，疲惫会休息，近期自主日程中的休养/温家问询优先。前台刷新显示，后台不承诺持续动画或系统推送。
- 主舞台、姐姐页及陪伴场景提供六项状态，展开可查看六条数值条、来源、恢复方法和近期来源账本。姐姐经验用每百点刻度显示，不代表突破。
- `character.vitals.version=1`：固定初值、稳定来源事件、冲突变体。气血为原 `character.health`，精力为 `100-fatigue`；其余资源按可信原事件重放，缓存条数值不是云端权威计数器。
- DDL 严重伤病消耗灵力28、姐姐经验30；已实际发生的净化传召（原 `result=summons`）消耗35/20，心情相应波动。每个原结算只生成一份来源回执。急性期灵力上限55，持续伤势上限75；不会二次扣气血、不改原DDL结算和人物境界。
- 首次迁移回填原伤病和已有可核对学习/日程，不对 HP 重罚；旧的误判撤销继续压过过期设备的结算。已撤销事件保留审计但不再扣资源。
- 姐姐经验独立于妹妹 `cultivation.xp` 与旧 `character.cultivation` 研习统计：每条实际完成学习每满30分钟贡献2，每日上限8；自主研习每日最多4，休养最多1。启动/暂停计时不产生奖励，重伤时自主研习不会发放高强度活动收益。
- 灵力夜间缓慢恢复，原日程休养、实际疗养每日有上限；原四步/最短三天重伤恢复条件保持。多个伤势的同日照护不刷多份资源收益。
- 饱腹按北京时间08/13/19自行用膳，离线同样计算，最低45；不会因为玩家不学习而挨饿。用膳/关怀各每日一次，有来源回执，不改变羁绊/主线。
- 事件按 ID 合并，重复跨设备照护的观察时间差规范到较早回执；相同来源的其他内容冲突保留全部变体，争议项暂停资源影响并可导出核对。原云端 CAS/鉴权/数据库/API 不变。
- 本次新增的资源状态随现有 JSON 和云存档保存。首次写入前保存原问道字符串于 `yuanhang_wendao_v1_before_v1_5`；原图缓存、六套立绘、CG、学习、记忆、伤势及剧情历史未清理。
- 陪伴本身无 AI 调用，且陪伴打开时暂停可选自动来信AI请求；用户主动自由聊天仍用原 Supabase `wendao-chat`、原认证和协议。聊天上下文只带六项派生快照，不发送整份资源事件账本。未修改或部署后端、密钥或费用限制。
- 原计时器加入在线单调时间对比：检测到设备时间明显跳变即暂停，不凭时钟跳进生成专注完成。关闭浏览器期间无法证明设备是否改时，保留原计时器重开结算能力；没有声称能识别所有离线时钟篡改。

## iPhone/Windows 待验与发布门槛

本环境为 managed container，缺少 control-browser，因此没有启动替代浏览器或把 DOM 测试描述为实际浏览器验收。本轮未访问真实手机/Windows存储、导出用户设备完整备份或代登录用户的云账户。

交接包 `01_可直接交给Codex.md` 明确要求「未经验收不要直接合并主分支或直接发布线上」；`03_验收方案.md` 要求真机与真实用户备份恢复验证。因此此分支待验，不直接合并或部署。此前用户确认 iPhone 可用指 v1.4.1，不能替代本轮 v1.5 验收。

2. Windows 浏览器检查进入/退出、六条状态展开、读剧情→陪伴→续读、25/45/60计时、暂停/恢复、取消重置和确认重置、完成记录只出现一次。
