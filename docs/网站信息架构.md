## 7. Obsidian → 网站流程

1. 在 Obsidian 中保留原笔记与附件；
2. 给准备进入网站的笔记增加统一 frontmatter；
3. 导入脚本读取指定文件夹，不扫描整个私人 Vault 后直接发布；
4. 导入时保留 `source_path`、原笔记链接与附件关系；
5. 自动做重复检测、必填字段校验、敏感信息扫描；
6. `private` 永不复制到公开构建目录；
7. `draft` 进入内容系统但不生成前台页面；
8. 只有 `public` 参与页面、搜索索引、站点地图和 RSS/分享元数据构建。

## 9. 搜索与筛选

首版搜索索引只包含：

- 标题、摘要、正文；
- 标签、地点、人物；
- 内容类型与年代；
- 公开来源说明。

档案筛选：年代、寄出地、接收地、主题、情感标签。实践筛选：地点、年份、形式。研究成果筛选：成果类型、阶段、状态。

`private` 不得进入浏览器端 JSON、静态产物、搜索索引、站点地图或页面源码；不能仅靠 CSS 隐藏。

## 10. 首页首版内容边界

第一版首页可以安全展示：

- 站点定位与侨批基础概念；
- 厦门、泉州、漳州三地实践入口；
- 五处场馆调研入口；
- 50 名学生参与的课程成果（待原始记录复核后展示数字）；
- 研究方法、文献综述、传媒索引；
- 《银信烽火》独立入口。

第一版首页暂不展示：

- 未核验的侨批馆藏数量、游客数量、合作机构数量；
- “省级二等奖”奖项卡片；
- 无原件图和授权的侨批卡片；
- 两份材料互相冲突的短视频数量；
- 任何个人联系方式、学号、预算或内部审批信息。

## 11. 代码阶段前置条件

继续 Phase 3 前必须取得原站源码或原 Git 仓库。拿到后应先：

1. 记录现有提交与线上版本；
2. 建立独立重构分支/检查点；
3. 运行现有构建，确认 Beta 可恢复；
4. 识别《银信烽火》的路由、状态、资产和数据依赖；
5. 先加总站壳层与内容加载器，再迁移入口；
6. 游戏核心页面不在首轮重写范围内；
7. 完成构建与部署验证后，再更新腾讯云线上版本。

## 12. 首版实现说明（2026-08-29）

首版总站已按上述结构落地。为兼容现有腾讯云 CloudBase 静态托管且不增加服务端重写依赖，路由采用 Hash 形式：`/#/栏目`。这不会改变信息架构，只影响浏览器地址表现；未来若迁移到支持 SPA fallback 或 SSR 的托管环境，可在保持内容模型不变的情况下切换为 History 路由。

《银信烽火》的完整体验路径为：

`首页 → 文创实验室 → 《银信烽火》成果档案 → 完整 Beta 体验`

档案库首版现在已接入 Campus 项目工作区的 `侨批资料分类索引 V1`：公开 68 条索引元数据（QP-001—QP-068），每条明确标注“待人工核验”，原件图仍只保留在 `source-assets/qiaopi-index-originals/`。`/archives/QP-001` 等页面是索引详情，不是已核验馆藏详情；唯一已发现的 1923 年菲律宾侨批线索仍保留在 `content/draft/archives/`，不会进入公开构建。
